# QA 清单 —— 三重深度检查（第一性原理 / 完备度 / 多设备 UI）

> **使用规则**：每一层检查按顺序执行、独立记录，任一层 fail 即返修，返修后**该层起重新跑完**（不允许"上次过了就跳过"）。检查结论写入交付报告（哪层、哪条目、结论、佐证）。
> 环境注意：主会话中用 `browser-use:control-browser` 技能控制浏览器做 C 层；**子代理中没有浏览器能力**（会报 "Browser is not available in subagent"），此时改用"本地无头浏览器 + CDP + console 监听"做同样的点击流，并把这条作为已知约束写入 QA 记录。

## A 层 · 第一性原理审计（游戏合理性与设计完备）

> 方法：从"玩家为什么要玩"向下一层层推：幻想 → 循环 → 数值 → 内容 → 呈现，任何断链都要回答"为什么应该存在"或删除。对照物是 game-bible.md。

A1 **核心幻想成立**：一句话定位里承诺的情绪，可以在 10 分钟内被体感（列出会触发该情绪的 3 个具体内容点，并确认它们都在数据表里）。
A2 **循环闭合**：数一遍"一个游戏日"里玩家能做的事，每个动作都有：成本（槽/精力/钱）→ 收益（数值/文本/关系）→ 下一步动机。找出没有"收益"或没有"成本"的动作，删或补。
A3 **稀缺性成立**：目标×时间是稀缺。检查：当日可做动作消耗的槽位总和 ≫ 时段数（选择有代价）；现金有正当出路（软骨：消费/礼物/房租/看病的支出点 ≥ 6 个）；精力妨碍无脑刷。
A4 **经济学自洽**：月固定支出（房租+吃穿+账单）写在纸上；第一月可入（工资+接单）≥ 支出的 1.2 倍且 ≤ 3 倍；首个大额目标（搬家/礼物/单）的攒钱天数在 3–20 天之间。
A5 **关系经济学**：从 0 心动到 100 心动的最快路径天数Listing（含加成减半）：`天数 = Σ(该路径事件 aff 累计)`；约会与主线进展的门槛（60 确认 / 82 离婚 / 88 求婚）可达且不偶然（列路径估算表）。加负反馈（生气/冷却/冷淡裂缝）能被触发。
A6 **事件权重合理**：`checkTriggers` 的概率表（62% 事件/25% 问候/10% 邀约/12% 糖）照抄即可但**频道清晰**；列出事件池 whose 频道计数，无频道 < 3 条。
A7 **凶手排除**：列出每个 `cond`，找"永远为真"和"永远为假"的条件（特别是玩不到就退化成摆设的系统）。
A8 **内容-主题契合**：每个系统（手机/工作台/地图/背包）都与题材语义咬合；纯套数不换义的系统（如苟在题材里无意义的"饱食度"）要么重命名语义要么砍掉。
A9 **爽点分布**：前 3 天有 ≥2 个"心跳时刻"（消息插入/初遇邀约/惊喜糖中任一）；每 1 个游戏月 ≥1 个里程碑（升职/纪念日/剧情幕）。
A10 **ント防错**：数值上限齐备（aff 100/心情 100/精力 cap）；负数的下限防线（现金不能为负——账本回滚存在）；防"重复点击堆叠事件"（pushOnce 型去重或场景屏）。
A11 **题材安全**：涉医疗/法务/金融的桥段有"游戏化简化"口径；分级门与免责声明伴随题材语境更新。
A12 **防白给**：结局无法靠无意义操作达成（fx ending 都挂在有叙事重量的选项上）；成就 test 函数人工推演三条能否达成。

## B 层 · 功能完备度审计（能不能被玩）

### B0 机械化 lint（必过，命令行）
```
node <skill>/scripts/qa_lint.mjs <game.html> --tier mini|standard|full
```
Exit 0 = 通过；error 必须修到 0；warning 逐条人工裁决（豁免理由写进 QA 记录）。骨架自身用 `--demo` 档校验。

### B1 十条点击流（每一轮构建完成后必跑）
用 C 层同一浏览器会话按下表点一遍（证据=步骤文本/数值截图）：

| # | 流程 | 通过判据 |
|---|---|---|
| 1 | 标题→门槛→新角色 | 创建后落在首页，状态卡数值完整 |
| 2 | 继续游戏 | 导入后同一日期/现金/关系数一致 |
| 3 | 下一天 ×3 | 日期 +3；现金每日-25..60；若触发事件则弹窗可关 |
| 4 | 下一个月 ×1 | 日期跨月；工资/房租有账本流水 |
| 5 | 城市任一地点→动作 | 时段 -1 或按动作语义生效；c كلsts 动作（见面）可遇 45% 率 |
| 6 | 初遇全流程 | _meet 场景出现 3 选项；关系变"相识" |
| 7 | 聊天 | 自由输入出 ≥1 条回复；话题库 3 天冷却生效 |
| 8 | 送礼三档 | 第三档余额不足时被拦截 toast |
| 9 | 工作/接单 | 上班 1 时段扣精力+口碑；接单 3 步 + 酬劳浮动结算 |
| 10 | 存档往返 | 手动存档 toast；导出文件可下载；删除前有确认 |

### B2 数据交叉引用（lint 已覆盖机械闭合，人补语义闭合）
- 每位主角：`lines` 八件套非空（meet/chatReply/dateArrive/near/night/morning/gift/sorry），topics ≥2 且话题文案非占位；heart[] ≥3；invite 文本（人物或 GAME_META.strings 兜底）。
- MEET_DEF ↔ PLACES ↔ 人物初遇线索三者互指一致。
- PLOT 幕的 `next` 链有出口（无永续卡幕）；`cond()` 条件在可达的 aff/stage 上。
- gam質判定 dc 与对应技能成长曲线匹配（≥dc 前该技能有1个获取渠道）。
- 成就/结局可 可达：列出每条达成条件被哪个内容动作点亮。
- 快进（force）丢弃可再生事件，保留剧情类（`opening_/初遇_/PLOT_/sys_eat 等`）——手动跑跳月确认不掉线。
- localStorage Quota 演算：把消息刷到 500+，确认 trim 生效不崩。

### B3 状态机边界
- 阶段机非法跳转有防线（ex 状态不可邀约；stranger 不可聊天——有提示）。
- 已婚离婚线（features 开）： divorcedForYou 后 confirmStageGate 能转 dating。
- `pending` 队列 drain：连按「下一天」验证 pending 逐个弹出（栈不冲突、无弹窗套弹窗交叠）。
- 快进期间 toast 提示丢弃数量（若有）。

## C 层 · 多设备 UI 适配审计

### C1 视口矩阵（截图证据，每图必拍）
- 手机竖屏 **320×568**（最小支持）、**375×812**（iPhone 基准）、**414×896**；
- 平板 **768×1024**；桌面 **1440×900**。
- 检查：480px 列居中画框、桌面下边框留白、datebar/topbar 不重叠；底部页签按钮高 ≥44px 触达。

### C2 竖屏动态与安全区
- `viewport-fit=cover` + `env(safe-area-inset-*)` 生效（有刘海框可用 devtools 模拟 iPhone 15 Pro 尺寸截 notch 区）。
- 页面滚动 `overscroll-behavior` 不穿透；弹窗内滚动独立（弹窗 max-height 86dvh）。
- 键盘弹起（聊天输入框）：页尾不被键盘顶没；输入框可见。

### C3 内容极值（改档玩到再文本）
- 最长人物名（≥6 字）在：人物卡/消息列表/动态流/聊天头部四处不溢出不折行错乱。
- 最大数值（¥1,000,000+）在 chips 与消息气泡不溢出。
- 最长场景 body（>400 字）滚动到底不盖按钮（scene 滚动可达 choices）。
- 消息流 100+ 条时 thread 打开仍流畅（懒加载/截断可用）。

### C4 主题可读性
- 正文对比 ≥4.5:1（取文本与背景最浅搭配实测一个值）；
- 文字系统字号：正文 ≥13px、副信息 ≥10px 且可读；
- 色弱可辨：关系标签(阶段/心动)不依赖颜色区分（有文字形徽章）。

### C5 端内外兼容
- 双击动荡：移动端 300ms tap 延迟不存在（用了现代触控模型）；
- `:active` 反馈实体按钮均存在（不"死按"）；
- 输入法回车触发不引发意外按钮（表单从 Enter 不提交）。
- 若支持桌面国产浏览器（可选）：Chrome/Edge 双引擎各开一次 title 与 core 流程。

### C6 交付出厂自检（打包前最后一遍）
- file:// 协议双击可玩（无 http 依赖）；断网玩 5 分钟无单点故障提示；
- 交付文件命名 `游戏名-版本号.html`（非 index.html，防误覆盖）；文件大小 < 2MB；
- `?v=` 缓存参数**不存在**（平台特化物——除部署参考文档腰，不写入游戏本体）。
