# WorkBuddy 云部署（可选 · 仅在交付确认之后）

> **何时读本页**：只有当 (a) 游戏已交付并通过 QA，且 (b) 用户在交付确认信息里明确回复"要部署"（或者主动提及 workbuddy/云平台/上链接时），才继续读。用户没提就**永不主动上传任何东西**。
> This is an optional final-deliverable add-on, never part of the game artifact itself.

---

## 背景

WorkBuddy 是一个支持"HTML 部署"技能的 AI 助手客户端：把本地静态目录（含 `index.html`）推送到云端静态托管，生成形如 `https://<账户哈希>.app.workbuddy.host/` 的公网链接（参考实现即部署于此平台，链接带 `?v=<日期>` 作缓存版本）。

**部署权在用户手里**：本 skill 只做"准备交付物 + 给操作指引"，不代用户登录、不代上传、不接触凭证。

## 操作流程（指引给用户/或经用户明确指令代传）

1. **准备交付物**：单文件游戏本体已是 `<游戏名>-<版本>.html`。为部署可复制/重命名一份为 `index.html`（WorkBuddy 静态托管按目录的 index.html 入口）。
2. **本地终检**（部署前 60 秒自检，全部必过）：
   - `node scripts/qa_lint.mjs index.html --tier <档位>` = PASS（特别确认 [E9] 反擦除全绿——**部署物里不得有任何 workbuddy/客服话术**）；
   - 浏览器直接打开 `index.html` 能完成「标题→创角→下一天」3 步。
3. **在 WorkBuddy 客户端操作**（需要用户的 WorkBuddy 账号）：
   - 安装/激活「HTMLDeploy」技能（如未安装）；
   - 把游戏文件放入一个只含该文件的文件夹，在该项目里发起部署指令（例：`部署这个文件夹里的 index.html`）；
   - 获得链接后验证：新开无痕窗口打开，重复本地 3 步终检。
4. **版本更新**：改动后重新部署即可。WorkBuddy 链接自带缓存策略；如需强制刷新，可在**分享给玩家时**在链接尾部附加 `?v=<日期>`——这是**用户侧操作**，不要写入 HTML 内部（qa_lint 会拦截游戏内缓存的 `?v=`）。

## 明确禁止

- 不会替用户上传任何含未通过 QA 的版本；
- 不在任何面向玩家的文案里写"技术维护/客服/QQ/学习资料/防盗"等平台特化话术；
- 不把本页流程合并进游戏交付说明（它仅属于"交付后询问"的分支）；
- 若用户托管到其他平台（网易/自建/OSS 等）：等价指引 = 找到"静态站点上传"入口 → 上传 index.html → 开无痕验证。把那句当作第 3 步替换即可。
